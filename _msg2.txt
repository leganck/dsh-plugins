code-index 0.4.0: 引入 tree-sitter AST 切块 + Cursor 风格的切块策略表（依赖按需安装）

## 需求
把 tree-sitter 作为依赖引入，并参考 Cursor 的「服务端按文件类型下发切块策略」
（GetAvailableChunkingStrategies）设置一套常用策略。

## 依赖：新增 parser 组，同样按需安装（不写进 package.json）
lib/deps.js 从"单一依赖组"扩展为依赖组机制，两组共用同一个受管目录与解析器链：
- embed：onnxruntime-node@1.30.0 + @huggingface/transformers@3.8.1（661 MB / 修剪后 264 MB）
- parser：tree-sitter@0.21.1 + java@0.21.0 + javascript@0.21.4 + typescript@0.21.2（41 MB）
实测 parser 组安装 3 秒（全部走预构建，零依赖脚本）。

## 版本配对：必须同年代，且只有"实际解析一次"才能验证
实测踩坑记录在 lib/deps.js 顶部：tree-sitter-java@0.23.5 声称 peerOptional tree-sitter@^0.21.1，
但预构建与 0.21.1 运行时不兼容——setLanguage 不报错、parse 也不报错，**读取节点时**才炸
`Cannot read properties of undefined (reading '138')`（数字是节点类型 id）。
最终可用组合：0.21.1 运行时 + java 0.21.0 / javascript 0.21.4 / typescript 0.21.2。

## 两个 tree-sitter 的坑（都在 lib/chunk-ast.js 里处理并写了测试）
1. **bufferSize 必须显式传**：默认 32 KB，字符串输入超过就抛 Invalid argument
   （二分实测 32767 通过 / 32768 失败）。只在真实仓库的大文件上才会暴露。
2. **setLanguage 必须传语法包的"元数据对象"，不能传它的 .language 子对象**：
   setLanguage 把参数原样存为 tree.language，之后 unmarshalNode 读它的 nodeSubclasses
   （由语法包的 nodeTypeInfo 派生）。传 .language 会以同样的 '138' 报错告终，
   但栈顶指向 tree-sitter 内部 index.js:771，与调用点无关——极难定位。
   tree-sitter-typescript 的导出是 {typescript, tsx}，要显式选变体。

## 策略表（lib/strategies.js，对应 Cursor 的服务端策略下发）
- ast（tree-sitter）/ heuristic（纯 JS，零依赖）/ window（固定窗口，明确指定给 Vue/XML/SQL/MD 这类文件）
- 按扩展名查表 + config.chunking.byExt 覆盖 + config.chunking.strategy 强制
- 降级链 ast → heuristic → window，每次降级都把原因带回并在建库结果里显式报告
- 收口阈值：minLines（短单元并入）/ targetLines（到量级就在成员边界收口）/ maxLines（强制拆分）

## 实测（真值来自语法树，"块首行落在成员内部"= 从方法中间开始）
| 仓库 | window | heuristic | ast |
|---|---|---|---|
| saas（8777 个 Java 文件，块数/平均行/首行在成员内）| 22619/33.3/29.4% | 18765/40.1/7.5% | 13156/45.1/**0.1%** |
| legacy-java-service（94 文件）| 207/32.3/15.0% | 179/37.4/6.1% | 122/43.4/**0.0%** |

过程中修掉两处自身缺陷（都是量测/测试抓出来的）：
- heuristic 原先切在每个成员边界 → 平均 15.6 行、48,372 块（向量要多算 3.7 倍）；
  加 targetLines 收口后降到 18,765 块、40.1 行，边界质量不变。
- 早前用"块内大括号是否平衡"当质量指标是错的：AST 块是"类里的一个方法"，天然不带类的 {，
  该指标把正确切法判成异常（ast 66.8% 反而"差于" heuristic 52.8%）。换成对称可比的
  "首行/末行是否落在成员内"。

## 一致性：策略指纹强制重建
建库写入 chunk_fingerprint；指纹变化自动全量重建并在结果里报告。
否则换策略后跑增量只会重切变动文件，库里会混着两种粒度的块且毫无信号。

## 其它修复
- getParser 未兜底 depsDir（配置默认 null）→ 默认安装下 AST 会**静默退化成启发式**，已修。
- 启发式切分条件原先只认 cur === base（顶层成员），对 Java 等于永不切分（成员全在 class 体里，
  深度 base+1），已改为同时认"下一行/这一行是成员声明"。
