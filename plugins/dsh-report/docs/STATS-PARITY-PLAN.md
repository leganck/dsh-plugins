# 统计页与 workbench 对齐计划（STATS-PARITY-PLAN）

> 结论先行：统计页的数据链路是通的（用你的真实库验证：`/line-stats` 近 12 个月返回
> 1365 提交 / 16 仓库 / 20 个 repoCards，`repoCards.excludeMerge` 内含每仓库 branch 与
> contributionDays）。差距主要在**交互与信息密度**，不是数据。

## 1. 当前已实现（对照 workbench SyncView 统计区）

- 标题（仓库名 + namespace + 不含合并和拣选）
- 快捷范围（近7天/近30天/本周/当月/上个月/近12个月）+ 日期范围 + 查询
- 贡献墙、摘要（提交/仓库/+/-）、覆盖度提示
- 提交记录：月 → 天 → 当天提交（时间/id/标题/合并·拣选标签/分支/仓库 chip/+/-）
- 左侧仓库树（计数、搜索、选中过滤）
- 同步数据对话框、生成报告入口
- 任务历史

## 2.1 本轮已完成（2026-11-07）

## 3. 里程碑

### M1（P0，进行中）
- S1 任务历史「查看统计」→ 回填范围 + 关闭对话框 + 加载
- S2 同步完成自动标记 stale，统计页再进入时刷新
- S3 生成报告 → 切到报告页并打开预填范围的生成对话框
- S4 同步仓库范围迁到设置（已完成）

验收：同步完成 → 任务行点「查看统计」→ 统计页范围=任务窗口且数据刷新；统计页点「生成报告」→ 报告页弹出预填对话框。

### M2（P1，与 workbench 信息密度对齐）
- S6 日期范围改 DSH 风格 date range（两个日期 chip + 快捷范围），不引第三方
- S5 分支条：全部仓库时展示「按仓库聚合的分支 top N」（workbench 只对选中仓库显示，按需做增强）
- S7 贡献墙桶：范围内 ≤ 3 个月按日、≤ 15 个月按周、否则按月（workbench `heatmapBucket`）
- 仓库树：当前范围下每仓库提交数/增删，仓库详情是否显示在右侧（workbench 是选中后标题变化）

### M3（P2）
- 生成报告后回跳统计并高亮范围；报告列表按范围过滤
- 空态/错误态统一为 DSH EmptyState/Tag
- 大范围性能：line-stats 1365 提交下首屏与切换仓库的耗时监控（目标 <300ms 渲染）

## 4. 验证方式

- 数据面：`/line-stats` 与 `/sync/jobs`、`/sync/coverage` 对照真实库
- 交互面：同步 → 查看统计 → 查询 → 选仓库 → 展开天 → 生成报告（预填）
- 视觉：主题 token、亮暗、与 DSH 原生页并排对比
