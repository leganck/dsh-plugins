# 会话唤醒（dsh-wake）

后台跑一个脚本。脚本往 stdout 打出一行标记时，把这一行投进发起会话，并开一轮。会话正忙时按「最新优先」处理，不堆积。

默认标记行：

```text
DSH_WAKE: 3 个 MR 已全部合并，可以创建发版分支
```

Agent 调用：

```text
wake_run({
  argv: ["node", "watch.mjs"],
  label: "等 MR 合并"
})
```

调完就可以结束本轮。脚本必须由 `wake_run` 启动；用户自己在终端里跑的进程不会唤醒会话。

## 投递方式

`mode` 决定消息怎么进会话：

| 值 | 会话空闲 | 会话忙碌（正在跑一轮） |
| --- | --- | --- |
| `auto`（默认） | 排队，开新一轮 | 压住最新一条，超时后插进当前回合（steer） |
| `queue` | 排队 | 排队（等这一轮结束） |
| `steer` | 排队 | 尽量插进当前回合 |

忙碌时最多压 `BUSY_HOLD_MS`（45 秒）：期间同一个 `key` 的多次触发只保留**最后一条**，超时后把最新那条插进当前回合。这样一次长任务不会把一堆积压消息留到最后才处理，过期的中间状态也不会被当成结论。

`key` 默认等于 `label`。同一会话、同一 `key` 只保留一条待投递消息；不同 `key`（比如部署监视和构建监视）互不影响。

## 在页面上看

每次 `wake_run` 都会登记成 DSH 的后台任务（job），所以在右侧「后台任务」面板里能看到：

- 任务名：`唤醒监视：<label>`
- 运行状态、实时输出（脚本打出的每次匹配行）
- 进度行：`等待中` / `已唤醒 N 次`，退出后变成 `exit code: N` 或 `已停止`
- 可以像 bash 后台任务一样直接终止

面板里终止等同于 `wake_stop`，不会再投递唤醒消息。拿不到 `jobs` 服务的部署会退回旧行为（不登记，只唤醒）。

## 其他行为

- 只匹配 stdout。stderr 不触发。
- 同一任务 1 秒内的多行只投递最后一行。
- 非 0 退出会再唤醒一次，带上退出码和 stderr 尾部；但如果这次监听已经报过标记行且没有 stderr，就不再补发，避免同一次失败收到两条消息。
- 0 退出且从没打出标记行，也唤醒一次，避免会话一直以为还在监听。
- `wake_stop` 只终止进程，不唤醒；该任务已压住但未投递的消息会一并丢弃。
- DSH 重启后不会自动重拉脚本。
