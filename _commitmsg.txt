code-index 0.3.0: 嵌入依赖改为运行时按需安装（装插件不再带 463 MB、不再要审批）

背景：0.2.1 把 onnxruntime-node / @huggingface/transformers 写进 optionalDependencies，
于是每次装插件都要下载落盘 463 MB、触发 pnpm/npm 的构建脚本审批，并且撞过一次
服务侧 idleTimeoutMs(600s) 空闲超时导致整次安装回滚。

实测确认可行性（本次新增的验证）：
- onnxruntime-node 的 npm 包自带各平台二进制（bin/napi-v6/...，整包 287 MB 里 133 MB 是 win32），
  所以 npm install --ignore-scripts 装完照样可用：require 成功、env.versions={common/node:1.30.0}、
  listSupportedBackends() = [cpu(bundled), dml(bundled), webgpu(bundled)]，DirectML 在。
  早期文档写的「原生二进制靠 postinstall 下载」是错的，已更正。
- 无脚本安装 46 秒 / 661.5 MB；修剪非本平台二进制后 263.8 MB（回收 397.7 MB），修剪后仍可用。

实现：
- 新增 lib/deps.js：受管目录（默认 %LOCALAPPDATA%/dsh-code-index/embed-deps）、状态、
  按需安装（--ignore-scripts；Windows 走 cmd.exe /c npm，因为 execFile('npm.cmd') 会 EINVAL）、
  修剪（只动 onnxruntime-node 底下的 napi-v*）、修复/删除、createRequire 解析器链。
- lib/embedder.js：改为从解析器链加载（受管目录优先，包内兜底），并区分
  「缺包」与「包在但加载失败」两种降级原因（后者早前被误报成前者）。
- index.js：新增 embedding.depsDir 配置（含校验）与第四个工具 code_index_deps
  （status/install/prune/repair/remove，默认只报状态，绝不擅自下载）。
- package.json：去掉 optionalDependencies 与 allowScripts；版本 0.2.1 -> 0.3.0。

测试：核心 53/53、插件接口 53/53（含 9 项新的依赖层断言）。过程中测试抓到两个真 bug：
修剪范围过宽（会删无关目录下的同名结构）、用 require.resolve('<pkg>/package.json') 判版本
在 exports 不暴露 package.json 的包上误报缺失。

装后实测：install_bundle 1.6 秒、pendingBuilds 无此键、零审批、Packages +1 -85。
